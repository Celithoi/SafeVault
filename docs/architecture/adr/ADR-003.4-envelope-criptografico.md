# ADR-003.4 --- Envelope Criptográfico

**Status:** 🟢 Approved\
**Versão:** 1.0 consolidada\
**Data:** 31/07/2026\
**Autor:** Marcelo Henrique Rocha Cardoso

## 1. Contexto

Clientes diferentes precisam transportar e persistir o resultado
criptográfico sem depender da API específica de uma biblioteca.

## 2. Decisão

O SafeVault utilizará um **envelope lógico estruturado e versionado**,
validado antes do uso criptográfico.

Componentes essenciais:

-   versão do envelope quando aplicável;
-   `cryptoVersion`;
-   algoritmo/identificação criptográfica quando exigido pela versão;
-   `nonce`;
-   `ciphertext`;
-   `tag`.

Campos binários utilizam representação textual interoperável definida
pelo contrato da versão.

## 3. Regras

-   envelope nunca contém plaintext;
-   nunca contém Master Password;
-   nunca contém Vault Key plaintext;
-   nunca contém chaves derivadas;
-   versões desconhecidas são rejeitadas;
-   campos obrigatórios inválidos são rejeitados;
-   interpretação é determinada pelo contrato documentado da versão;
-   campos adicionais não podem silenciosamente alterar semântica
    criptográfica.

## 4. Decisões Formalmente Aprovadas

-   ✅ Envelope explícito e versionado.
-   ✅ Contrato compartilhado entre clientes.
-   ✅ Validação estrutural antes da descriptografia.
-   ✅ Separação lógica de nonce, ciphertext e tag.
-   ✅ Nenhum segredo ou plaintext no envelope.
