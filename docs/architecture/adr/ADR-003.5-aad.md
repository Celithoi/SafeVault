# ADR-003.5 --- Additional Authenticated Data (AAD)

**Status:** 🔵 Revised\
**Versão:** 1.1 consolidada\
**Data original:** 31/07/2026\
**Revisão:** 30/08/2026\
**Autor:** Marcelo Henrique Rocha Cardoso

## 1. Contexto

O AAD do AES-GCM deve vincular o ciphertext ao contexto criptográfico
correto sem expor metadados funcionais desnecessários.

A versão inicial desta ADR incluía `userId` e `itemType`. O cross-check
com o Core Data Model da ADR-005 mostrou que isso conflitava com a
minimização de metadata e com a relação de ownership
`User → Vault → VaultItem`.

## 2. Decisão Vigente

Para `VaultItem`, o AAD utiliza classificação criptográfica
**genérica**, e não o subtipo funcional do item.

Conceitualmente:

``` text
domain = safevault:vault-item
cryptoVersion
vaultId
itemId
```

A representação concreta deve ser **canônica e determinística**.

## 3. Correções da Revisão 1.1

-   `itemType` funcional (`LOGIN`, `SECURE_NOTE`, etc.) **não pertence
    ao AAD** e permanece dentro do payload criptografado.
-   `userId` foi removido do AAD do `VaultItem`.
-   Ownership é vinculado criptograficamente ao contexto
    `vaultId + itemId`.
-   O domínio é genérico para a classe criptográfica do objeto.
-   AAD não contém conteúdo sensível.

## 4. Serialização

Todos os clientes devem produzir a mesma sequência de bytes para o mesmo
AAD lógico.

A serialização deve possuir regras explícitas e determinísticas de:

-   campos;
-   ordem/canonicalização;
-   tipos;
-   encoding;
-   ausência/presença de campos.

## 5. Limite de Segurança

AAD impede reutilização válida do ciphertext em contexto diferente
quando o contexto esperado está vinculado.

AAD **não prova freshness** e não impede sozinho que um servidor
malicioso restaure uma versão antiga válida do mesmo item. Essa
dependência permanece na ADR-003.8.

## 6. Decisões Formalmente Aprovadas

-   ✅ AAD protege contexto criptográfico, não dados de UI.
-   ✅ `itemType` funcional permanece criptografado.
-   ✅ `userId` não pertence ao AAD de `VaultItem`.
-   ✅ `vaultId` e `itemId` vinculam o item ao contexto esperado.
-   ✅ Serialização canônica/determinística.
-   ✅ Alteração do AAD esperado invalida autenticação AEAD.
-   ⏸ Anti-rollback/freshness pertence à ADR-003.8.
